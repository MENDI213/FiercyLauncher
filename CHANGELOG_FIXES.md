# FiercyLauncher — встроенные подробности Modrinth и горячие клавиши

## Навигация и удобство оконного режима
- Стартовое окно увеличено, чтобы каталог и основные действия были удобны без разворачивания на весь экран; фактические размеры ограничиваются доступной областью монитора.
- Добавлены базовые горячие клавиши: Esc закрывает открытый просмотр/центр активности/встроенные подробности, боковая кнопка мыши «Назад» возвращает по истории экранов, а «Вперёд» перемещается вперёд. Для открытых диалогов боковая кнопка «Назад» закрывает диалог.
- В настройках добавлены две зависимые опции: включение базовых горячих клавиш и отдельное включение расширенных сочетаний. Расширенные клавиши можно назначить на разделы, запуск игры, загрузки, уведомления и поиск; настройки сохраняются общей кнопкой сохранения.

## Подробности Modrinth
- Подробности проекта теперь отображаются внутри рабочей области каталога, без отдельного системного окна и его белой заголовочной полосы.
- Исправлен `NameError` галереи: `ModrinthImageWorker` импортируется непосредственно в момент запуска загрузки изображений, без циклического импорта модуля.
- Галерея показывает изображения проекта, позволяет перелистывать весь список снимков (в том числе пока следующие изображения загружаются) и раскрывать изображение поверх всей области окна лаунчера. Esc закрывает просмотр, затем подробности.
- Обработчики завершения загрузок галереи используют безопасную очистку при закрытии страницы, чтобы не обращаться к уничтоженным виджетам.

## Отрисовка фона
- Скруглённый clip-path фона строится через числовую перегрузку `QPainterPath.addRoundedRect`, поэтому больше не зависит от импорта `QRectF` и не вызывает `NameError` в `paintEvent`.

Проверка: Python compileall и 54 unit-теста прошли. PyQt5 в среде сборки отсутствует, поэтому GUI smoke-test необходимо выполнить в Windows.

# FiercyLauncher — стабильность карточек, прогресс загрузок и отмена

## Карточки модов и сборок
- Окно подробностей открывается только после обычного левого клика внутри карточки; нажатия на кнопки действий не перехватываются карточкой.
- Проверяются ID и формат ответа Modrinth, а длинные/некорректные описания ограничиваются и безопасно очищаются перед отображением.
- Загрузка изображений в карточках и галерее ограничена по размеру и разрешению до декодирования, чтобы большие изображения не перегружали Qt.

## Прогресс и управление загрузками
- При установке Minecraft и NeoForge показываются процент текущего файла, переданный объём, общий размер файла и скорость в МБ/с.
- Загрузка модов и файлов готовых сборок Modrinth/CurseForge показывает процент, объём и скорость; после завершения также отправляется финальное состояние 100%.
- У установки Minecraft/загрузчика и импорта модпака есть штатная отмена через сигнал остановки. Временный недокачанный файл не принимается как готовый.
- В карточке каталога можно убрать задачу из очереди или остановить уже начавшуюся загрузку; после остановки карточка возвращается в состояние «Скачать».

## Персонализация
- В настройках можно выбрать собственную фотографию фона или вернуть стандартный фон Fiercy.
- Изображение кадрируется под размер окна, получает затемняющий слой для читаемости интерфейса и сохраняется в настройках вместе с остальным оформлением.
- Сброс оформления также очищает выбранный фон.

## Согласованность версии и проверка
- Удалена лишняя строка в `version.py`, из-за которой запуск завершался `NameError`; локальная версия согласована с включённой конфигурацией `1.0.0.8`.
- Проверка: `python -m compileall -q .` и `PYTHONPATH=. python -m pytest -q` — 49 тестов прошли.
- Полный GUI smoke-test здесь не запускался: в среде проверки не установлены PyQt5 и minecraft-launcher-lib.

# FiercyLauncher — исправления интерфейса профилей и Modrinth

## Профили и сборки
- После создания профиля установка больше не запускается автоматически: пользователь может сначала сменить версию Minecraft, загрузчик и версию загрузчика.
- Версия загрузчика сохраняется только для соответствующей пары Minecraft + loader; при смене Minecraft/loader список обновляется.
- Вкладка «Каталог модов» скрывает блоки настройки и импорта, оставляя выбор профиля и освобождая основную высоту окна под каталог.
- Действия с файлами/параметрами визуально отделены от установки/запуска.

## Установленные моды
- Список стал выше и прокручивается внутри своей области.
- Рядом с модом отображается checkbox для включения/отключения, иконка и название.
- По названию открывается страница Modrinth (или поиск), ПКМ открывает удаление.
- Поиск и извлечение иконок поддерживают общие пути, Fabric `fabric.mod.json` icon и Forge/NeoForge `logoFile`.

## Modrinth
- При добавлении страниц не перестраивается вся сетка; лишняя повторная компоновка пропускается.
- Описания очищаются от внешних изображений/HTML, которые QTextBrowser отображал как битые значки; галерея остаётся отдельной, изображения открываются в просмотрщике.
- Загрузки изображений управляются главным окном, чтобы закрытие диалога не уничтожало работающие QThread.
- Типы контента вынесены в отдельные кнопки: моды, ресурспаки, шейдеры, готовые сборки.

## NeoForge
- Скачивание официального installer JAR выполняется с таймаутом подключения 25 секунд и тремя повторными попытками; частичный файл не оставляется.
- ConnectTimeout показывает точную официальную ссылку и путь кэширования.
- В настройках профиля NeoForge доступна прямая загрузка через браузер как обходной путь при проблемах Python HTTPS.
- После ручного скачивания JAR можно положить в `.fiercy/installers` и повторить установку.

## Производительность
- Перетаскивание ползунков меняет только значение и подпись; полная регенерация QSS выполняется после отпускания.
- Ограничена повторная перестройка сетки Modrinth, изображения загружаются ограниченным числом потоков.

Проверка: Python compileall и 14 unit-тестов прошли в среде сборки. Полный GUI smoke-test на Windows требует PyQt5 и minecraft-launcher-lib и здесь не выполнялся.

## Ускорение автообновления и обновление до открытия главного окна

- Проверка GitHub Releases перенесена в стартовый bootstrap-экран до импорта и открытия основного окна.
- При включённом автообновлении архив загружается в стартовом окне, затем сверяется SHA-256, передаётся отдельному помощнику установки, а приложение закрывается и запускается заново уже из обновлённых файлов.
- Для больших ZIP используется до 8 параллельных HTTP Range-запросов, если CDN подтверждает поддержку диапазонов; иначе автоматически применяется обычная загрузка с тремя попытками.
- Загрузка используется и в ручной проверке обновлений. Проверенный ZIP кешируется и повторно не скачивается.
- Если GitHub недоступен или обновление не удалось скачать/применить, текущая версия запускается без повреждения установленных файлов.


## Исправления установщика: читаемый ярлык и быстрая загрузка

- Чекбокс создания ярлыка вынесен в отдельную контрастную карточку; увеличены размер текста и индикатора, добавлено понятное пояснение.
- Установщик увеличен, чтобы элементы не выглядели сжатыми.
- Загрузка `FiercyLauncher-win64.zip` в setup переведена на общий проверенный загрузчик `update_download.download_verified_asset`.
- Используются до 8 параллельных HTTP Range-потоков, если GitHub CDN поддерживает Range; в противном случае автоматически остаётся обычная загрузка с повторами.
- Во время скачивания теперь показываются фактическая скорость, объём и режим загрузки.
- SHA-256 проверяется до сохранения архива в кеш; повреждённый пакет не устанавливается.
- PyInstaller setup spec явно включает `update_download`.


## NeoForge installer compatibility

- Prepare `launcher_profiles.json` for the official NeoForge LegacyInstaller when the game directory belongs to a third-party launcher and has no official-launcher profile. Existing files are preserved; malformed files are not overwritten.
- Run the installer with an explicit absolute target and the target directory as its working directory.
- Validate the generated NeoForge version JSON (`id`, `inheritsFrom`, `mainClass`, `libraries`) before reporting the build as installed. Include the installer's log on failures.
- Support both official Maven coordinate families: `net.neoforged:forge` for Minecraft 1.20.1 and `net.neoforged:neoforge` for 1.20.2+ and modern year-based versions such as Minecraft 26.3.
- Add tests for the launcher profile bootstrap, Maven coordinates, stable version filtering and installed profile validation.
- Fix missing `json` import used by Modrinth install metadata persistence.

- For supported classic `1.x` Minecraft releases, installation now delegates to `minecraft_launcher_lib.mod_loader.get_mod_loader("neoforge").install(...)`. This library adapter ensures the vanilla launcher profile exists, runs the official `--install-client` installer, and completes the inherited child-version files through `install_minecraft_version`.
- For Minecraft 26.x (not normalized correctly by the library's current NeoForge adapter) and the special Minecraft 1.20.1 coordinate family, use the explicit Maven-aware fallback, then complete the child profile through minecraft-launcher-lib.
- NeoForge launch remains through `minecraft_launcher_lib.command.get_minecraft_command`, with version metadata validated before enabling Play.


## NeoForge: установку привели к штатному сценарию minecraft-launcher-lib

- Причина ошибки из лога: официальный LegacyInstaller завершался сообщением `There is no minecraft launcher profile` — в `D:\FiercyLauncher` отсутствовал `launcher_profiles.json`. Это не была ошибка Java или скачивания JAR.
- Перед установкой теперь гарантированно создаётся минимальный `launcher_profiles.json` структуры v3 (`profiles`, `settings`, `version: 3`); существующий файл не перезаписывается, повреждённый не затирается.
- Для обычных Minecraft 1.x (кроме старой координатной схемы 1.20.1) используется штатный `minecraft-launcher-lib 8.x` NeoForge adapter: проверка поддержки версии, vanilla dependencies, официальный installer с `--install-client`, а затем установка наследуемой версии и библиотек.
- Для Minecraft 1.20.1 (`net.neoforged:forge`) и современных year-based версий вроде 26.3 оставлен Maven-aware fallback, потому что текущий adapter библиотеки нормализует Minecraft-версии только в формате 1.x. После официального installer зависимости дочерней версии завершаются через `minecraft-launcher-lib`.
- Один и тот же установочный маршрут теперь используется и для обычного создания сборки, и для импорта готового Modrinth/CurseForge modpack.
- Поддержана загрузка списка стабильных NeoForge версий для Minecraft 26.3; предыдущий парсер ошибочно требовал версию Minecraft, начинающуюся с `1.`.
- Перед запуском проверяется сгенерированный version JSON, его `id`, `inheritsFrom`, `mainClass` и `libraries`. Запуск по-прежнему формируется через `minecraft_launcher_lib.command.get_minecraft_command`, как и для Vanilla/Forge/Fabric.

Проверка: Python compileall и 27 unit-тестов прошли. Реальный вызов Java installer и GUI на Windows в среде разработки не запускались.

## Переработка раздела «Моды и сборки» и главного выбора игры

- Раздел «Моды и сборки» теперь открывается сразу на полноценном каталоге готовых Modrinth-сборок; сверху вынесены отдельные действия «Каталог сборок», «Создать сборку» и «Мои сборки».
- Создание сборки по-прежнему использует отдельную форму с названием, версией Minecraft, загрузчиком и версией загрузчика; после создания лаунчер сразу переводит пользователя в «Мои сборки».
- Рабочая область «Мои сборки» отделена от каталога. В ней остаются параметры сборки, установка/запуск и управление установленными модами.
- При первом открытии каталога выбран тип «Готовые сборки», поэтому его можно просматривать и устанавливать без предварительно созданного профиля.
- Каталог модов, ресурспаков и шейдеров требует выбранную сборку; фильтры остаются отдельными и учитывают её версию Minecraft и загрузчик.
- Убрана кнопка ручной пагинации. Следующая страница Modrinth подгружается автоматически при приближении к концу списка; если первая страница не заполняет область, подгрузка продолжается до появления прокрутки.
- Каталог прокручивается в пикселях, получил более крупную рабочую область и поддержку кинетической прокрутки на сенсорных экранах. При добавлении результатов сохраняется позиция списка.
- В главном меню запуска список теперь показывает понятные названия: «Minecraft 1.21.1» для обычных версий и название пользовательской сборки для установленных профилей. Кнопка «Играть» запускает выбранный тип правильным игровым каталогом.
- Переписаны основные заголовки и пояснения на главной странице и в разделе сборок: убраны шаблонные лозунги и технические формулировки, оставлены короткие понятные действия.

Проверка этой редакции: `compileall` успешен; 15 unit-тестов прошли. PyQt5 отсутствует в среде сборки, поэтому реальный визуальный smoke-test и запуск Minecraft на Windows не выполнялись.


## 1.0.0.7 — каталог, параллельная установка и плавность

- В каталоге явно показан выбор целевой сборки; установка модов, ресурспаков и шейдеров выполняется только в выбранную сборку.
- При переключении сборки карточки пересчитывают состояние именно для неё; пустой пункт «Выбери сборку» больше не подменяется активной сборкой.
- Карточки Modrinth различают «Скачать», «В очереди», «Скачивание», «Установлено» и «Повторить». После установки доступна отдельная кнопка удаления.
- Очередь ограничивает число одновременных worker-потоков четырьмя; загрузки разных проектов не блокируют запуск друг друга.
- Убраны полноэкранные opacity-анимации QGraphicsEffect, добавлена touch/kinetic scroll поддержка основным областям прокрутки.
- Боковая панель не содержит подписи «Тема и настройки персонализируются».
- Discord без Application ID использует штатное обнаружение зарегистрированного FiercyLauncher.exe; расширенный RPC остаётся опциональным.


## 1.0.0.8 — hotfix HTTPS для публичной беты

- Исправлена упаковка CA bundle: portable ZIP больше не удаляет публичный `certifi/cacert.pem` вместе с приватными PEM-файлами.
- `launcher.spec` и `fiercy_setup.spec` явно включают данные certifi и runtime hook для TLS.
- Добавлена ранняя проверка HTTPS CA bundle без отключения проверки сертификатов.
- `package_release.py` сохраняет только корректный `certifi/cacert.pem`; остальные PEM, приватные ключи и секреты продолжают исключаться.
- Сборка останавливается, если CA bundle отсутствует в итоговом onedir каталоге или portable ZIP.
- Версия клиента и публичные JSON обновлены до 1.0.0.8.


## Центр загрузок, уведомления и адаптивное оформление

- Главное окно теперь запускается в компактном размере, рассчитанном по доступной области экрана; при уменьшении окна автоматически уплотняются отступы, размеры элементов и ширина боковой панели. Полноэкранный режим сохраняется.
- В настройках оформления добавлена регулировка непрозрачности панелей: фон пользователя просвечивает через окно, заголовок, боковую панель и карточки. Обои рисуются с тем же скруглением, что и окно.
- В верхней панели появилась кнопка истории уведомлений. История сохраняется между запусками, непрочитанное количество отображается на кнопке, доступны фильтры по типам и очистка прочитанных записей.
- Слева снизу добавлен центр загрузок. В нём представлены отдельные задачи Minecraft/NeoForge, Modrinth-модов, импорта сборок и обновления лаунчера; поддерживаемые операции можно приостанавливать, продолжать, отменять и убирать из списка.
- Общий ограничитель скорости действует на поддерживаемые параллельные загрузки вместе; значение 0 снимает ограничение.
- При недоступной обязательной зависимости Modrinth установка основного мода продолжается, а пропущенные зависимости перечисляются в отдельном предупреждении.
- Discord-настройки сокращены. Сохранён менеджер Rich Presence, который показывает версию Minecraft и ник игрока при наличии настоящего Discord Application ID. Удалён вводящий в заблуждение тестовый ID из приложенного старого скрипта.
- Завершённые задачи освобождают ссылки на QThread, но остаются в истории центра активности до ручного удаления.
- Добавлены тесты паузы, продолжения, отмены и настройки общего ограничителя скорости.

Проверка: Python compileall и 54 unit-теста прошли. GUI smoke-test в этой среде не выполнялся: отсутствуют PyQt5 и minecraft-launcher-lib.

## Стартовое обновление: окно и измерение скорости

- Стартовый экран обновления больше не является frameless/always-on-top окном: у него обычная системная панель заголовка, его можно перемещать, сворачивать и перекрывать другими окнами.
- Размер стартового окна немного увеличен; кнопка закрытия в заголовке штатно отменяет текущую проверку/загрузку.
- Для загрузки GitHub Release скорость теперь рассчитывается по скользящему окну последних трёх секунд, а не как средняя скорость с начала операции. Долгое ожидание CDN и паузы больше не занижают отображаемую текущую скорость на весь остаток загрузки.
- Если CDN подтверждает HTTP Range, стартовый загрузчик использует до 12 параллельных диапазонов вместо 8. Если Range недоступен, остаётся безопасный однопоточный режим с повторами и проверкой SHA-256.
- Добавлены unit-тесты скорости на длительном ожидании первого блока и при повторном старте диапазона.

Проверка: Python compileall и 56 unit-тестов прошли. Проверка визуального поведения системного заголовка на Windows требует запуска на Windows и здесь не выполнялась.
