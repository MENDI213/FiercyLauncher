# FiercyLauncher — обычные версии Minecraft, сборки и каталог Modrinth

Эта редакция развивает проект FiercyLauncher на PyQt5. Для обновлений приложения и публичных новостей собственного VPS не требуется: сборки публикуются в GitHub Releases, а новости и параметры читаются из JSON в репозитории.

## Что входит в бета-версию 1.0.0.4

- **Колесо мыши больше не меняет настройки.** Списки, поля с числами, слайдеры и выбор шрифта игнорируют `wheelEvent`: колесо прокручивает страницу. Значение меняется только явным выбором/перетаскиванием/вводом.
- **Защита настроек от выхода.** Любое изменение помечается как черновик. Нельзя перейти на другую вкладку или закрыть лаунчер, пока не нажата кнопка «Сохранить все настройки». Предварительный просмотр темы не записывается автоматически.
- **Режим слабого ПК включён по умолчанию.** Тени отключены, анимации страниц отключены, чтение логов выполняется раз в 7 секунд и только когда открыта вкладка логов. Сетевые запросы, установка игры, импорт и обновления работают в `QThread`, не блокируя интерфейс.
- **Обычная игра без профиля.** На вкладке «Игра» выбирается любая официальная версия Minecraft: релиз, снапшот или старая Beta/Alpha. Тип версии виден прямо в списке. Игра устанавливается в основной каталог и запускается напрямую; профиль для обычной Vanilla-игры не создаётся и не требуется.
- **Отдельные сборки.** На вкладке «Моды и сборки» можно создать сборку: выбрать её имя, версию Minecraft, загрузчик и его первоначальную версию. После создания версия Minecraft и тип загрузчика фиксируются, а версию самого загрузчика можно менять отдельно. Каждая сборка имеет собственные моды, конфиги, сохранения, ресурспаки и шейдеры.
- **Общее хранилище игры.** `versions`, `libraries`, `assets` и `runtime` хранятся один раз в корне FiercyLauncher. У каждого профиля свои `mods`, `config`, `saves`, `resourcepacks`, `shaderpacks` и `screenshots`.
- **Каталог Modrinth.** Каталог сразу показывает популярные моды, ресурспаки, шейдеры и модпаки. Карточки содержат иконку, описание, автора, число загрузок и добавлений в избранное. По нажатию открываются описание, галерея и совместимые версии. Modrinth не требует API-ключа.
- **Локальные карты.** ZIP-карту можно импортировать в выбранную сборку; архив проверяется на наличие `level.dat` и небезопасные пути перед распаковкой.
- **Импорт сборок.** Поддерживается Modrinth `.mrpack` и импорт локальной версии из корневой папки `.minecraft` другого лаунчера. Импорт переносит version JSON вместе с цепочкой `inheritsFrom`, библиотеки, assets, runtime, mods, configs и saves.
- **Локальные версии.** Если вручную положить валидную папку версии в `FiercyLauncher/versions/<version-id>/`, её можно обнаружить кнопкой обновления списка. Кнопка «Открыть общую папку versions» открывает нужное место.
- **FiercyCity.** Добавлена отдельная вкладка-каркас. Каталог и управление онлайн-сборками подключаются позже к API/VPS; сейчас можно импортировать локальную сборку.
- **GitHub auto-update.** При старте лаунчер сравнивает локальную версию с GitHub Release. По умолчанию обновление скачивается автоматически, проверяется SHA-256 и устанавливается отдельным helper-процессом после закрытия главного EXE. Загруженный ZIP повторно используется из кеша, только если SHA-256 всё ещё совпадает.
- **FiercySetup.exe.** Отдельный bootstrap installer скачивает последнюю Windows-сборку с GitHub, проверяет SHA-256, использует кеш версий и устанавливает файлы в выбранную папку `FiercyLauncher`.

## Важное ограничение авторизации

В проекте **не реализован запуск платной Minecraft Java Edition с произвольным ником и сгенерированным offline UUID без подтверждения владения игрой**. В этой сборке остаётся Microsoft OAuth и проверка официального Minecraft-профиля. После подтверждения данные сессии сохраняются в Windows Credential Manager через `keyring`, поэтому браузер не нужен при каждом запуске, пока сессия действительна.

Это ограничение относится к аутентификации лаунчера, а не к наличию многопользовательского сервера: одиночные миры хранятся локально в папке профиля `saves`, отдельный сервер для одиночной игры не нужен. После успешного входа лаунчер сохраняет подтверждённый профиль и может попробовать запустить уже установленную игру с кешированной сессией без сети; это сработает только пока Minecraft принимает сохранённый access token. После его истечения потребуется подключение к интернету для обновления сессии. Ввести произвольный ник вместо владельца Minecraft Java Edition этот проект не позволяет.

## Требования

- Windows 10/11 x64 для готового EXE.
- Python 3.11+ для запуска из исходников; Python 3.12 x64 рекомендуется для сборки Windows EXE.
- Интернет нужен для первого получения Minecraft/загрузчика/Java, поиска модов и получения обновлений. После установки локальная папка игры остаётся доступной без скачивания тех же файлов повторно.
- Каталог использует публичный API Modrinth; личный API-ключ игроку не нужен. CurseForge-каталог не используется.

## Запуск из исходников — с нуля

1. Установи **Python 3.12 x64** с официального сайта Python. В установщике включи пункт `Add Python to PATH`.
2. Скачай `FiercyLauncher-source.zip` и распакуй, например, в `D:\FiercyLauncher-Source`.
3. Открой распакованную папку и дважды нажми `run_windows.bat`.
4. BAT-файл создаст `.venv`, установит всё из `requirements.txt` и запустит `main.py`.
5. На вкладке «Игра» выбери обычный релиз Minecraft, нажми «Установить», а затем «Играть». Для модовой сборки отдельно открой «Моды и сборки», создай профиль, выбери Minecraft и загрузчик и установи сборку.
6. Для первого подключения официального игрового профиля укажи Microsoft Entra Client ID в настройках и заверши OAuth. Не публикуй токены или ключи в GitHub.

Если Windows показывает предупреждение SmartScreen для самостоятельно собранного EXE, это связано с отсутствием подписи издателя. Не скачивай EXE из посторонних источников; используй артефакты своего GitHub Release или собери локально.

## Как устроены игровые данные

Если в настройках выбрать родительскую папку `D:\dodo`, лаунчер создаст и использует:

```text
D:\dodo\FiercyLauncher\
├── versions\                 # общие JSON/JAR версий
├── libraries\                # общие библиотеки
├── assets\                   # общие игровые assets
├── runtime\                  # Java runtime
├── instances\
│   ├── <profile-id-1>\
│   │   ├── mods\
│   │   ├── config\
│   │   ├── saves\
│   │   ├── resourcepacks\
│   │   ├── shaderpacks\
│   │   └── screenshots\
│   └── <profile-id-2>\
└── .fiercy\profiles.json     # реестр профилей
```

Если выбрать уже существующую папку с именем `FiercyLauncher`, второй одноимённый уровень не создаётся. При смене корня лаунчер сначала объединяет старые данные с новым расположением; перенос внутрь самой старой папки или в её родителя запрещается, чтобы избежать рекурсивного копирования.

### Импорт локальной сборки из другого лаунчера

1. Убедись, что у сборки есть версия в `versions/<id>/<id>.json`.
2. В FiercyLauncher открой «Моды и сборки» → «Импортировать локальную версию». Импорт создаёт отдельный профиль и переносит туда профильные каталоги. Дополнительно можно открыть общую папку `versions`, вручную скопировать туда папку своей версии с JSON и JAR, а затем на вкладке «Игра» нажать кнопку обновления списка установленных версий (круглая стрелка справа от селектора запуска).
3. Выбери корневую папку `.minecraft` (или папку игры, внутри которой есть `versions`, `libraries` и `assets`).
4. Выбери нужный ID версии. Лаунчер скопирует версию и её родительские JSON в общее `versions`, общие библиотеки/assets/runtime и профильные `mods/config/saves` в новую папку профиля.

Если используешь Prism Launcher или Modrinth App, сначала открой папку конкретного инстанса и выбери именно его `.minecraft`, если она есть. Для другого формата можно вручную скопировать каталог версии в общую папку `versions`, а `.jar` моды и конфиги — в `instances/<profile-id>`. После ручного копирования нажми обновление списка установленных версий; выбери импортированный ID в селекторе запуска.

### Импорт готового модпака

- Modrinth: импортируй `.mrpack`. Лаунчер прочитает `modrinth.index.json`, установит Minecraft и загрузчик, скачает файлы с проверкой хешей и распакует overrides.
- CurseForge не подключён: лаунчер использует Modrinth, чтобы игрокам не приходилось получать и вводить персональные API-ключи.

### Управление модами

Открой профиль и его список модов. Дважды кликни по моду или используй кнопку «Включить / отключить». Отключённые файлы получают расширение `.jar.disabled` и не загружаются Minecraft. В каталоге Modrinth можно открыть карточку проекта, посмотреть описание, галерею и версии, а затем установить подходящий файл в активную сборку. Моды должны соответствовать версии Minecraft и загрузчику профиля. Ресурспаки и шейдеры устанавливаются в отдельные каталоги; ZIP-карты импортируются в `saves`.

## Как собрать EXE на своём компьютере

1. На Windows открой папку проекта.
2. Запусти `build_windows.bat`.
3. Скрипт создаст `.venv`, установит зависимости, соберёт главное приложение, `FiercyUpdater.exe`, `FiercySetup.exe` и архивы.
4. Готовое приложение находится в `dist\FiercyLauncher\FiercyLauncher.exe` вместе со вспомогательными файлами в этой же папке.
5. Установщик находится в `dist\setup\FiercySetup.exe`.
6. Архивы и SHA256SUMS появляются в `release_assets\`.

Не отправляй только `FiercyLauncher.exe`: PyInstaller собирает приложение в режиме `onedir`, рядом обязательна папка `_internal` и `FiercyUpdater.exe`.

## GitHub — публикация и обновления без VPS

В исходнике сейчас задан репозиторий `MENDI213/FiercyLauncher` в `version.py` и `fiercy_setup.py`. Если используешь другой репозиторий, поменяй `GITHUB_REPOSITORY` в `version.py` и `REPOSITORY` в `fiercy_setup.py`.

### Первичная загрузка проекта

1. Установи GitHub Desktop и войди в GitHub.
2. В GitHub Desktop выбери `File → Clone repository` и клонируй `MENDI213/FiercyLauncher` на компьютер.
3. Закрой лаунчер, сделай резервную копию старой папки проекта.
4. Распакуй новую версию поверх клонированной папки с заменой файлов. **Не удаляй скрытую папку `.git`** — в ней находится связь с GitHub. Скопируй также скрытую папку `.github` с workflow-файлами.
5. В GitHub Desktop проверь список изменений, введи сообщение `FiercyLauncher 1.0.0.4: beta hardening and UI cleanup` и нажми `Commit to main`, затем `Push origin`.

### Публикация новой версии

1. Перед релизом измени номер в `version.py` или выполни в папке проекта:

   ```bat
   py set_version.py 1.0.0.5
   ```

2. Сохрани изменения, закоммить и отправь их в `main`.
3. Открой PowerShell в папке проекта и выполни:

   ```powershell
   git tag v1.0.0.5
   git push origin v1.0.0.5
   ```

4. Открой репозиторий на GitHub → вкладка **Actions**. Workflow `Build and publish launcher release` запустится на GitHub Windows runner.
5. После успешной сборки открой **Releases**. Workflow прикрепит `FiercyLauncher-source.zip`, `FiercyLauncher-win64.zip`, `FiercySetup.exe` и `SHA256SUMS.txt`.

Для работы workflow в репозитории открой `Settings → Actions → General → Workflow permissions` и включи `Read and write permissions`, если политика репозитория не даёт workflow создавать Releases.

### Как работает автообновление

1. При запуске клиент обращается к `https://api.github.com/repos/MENDI213/FiercyLauncher/releases?per_page=20`.
2. Сравнивает `tag_name` релиза с `LAUNCHER_VERSION` через `packaging.version`.
3. Загружает ZIP нужного типа: `FiercyLauncher-win64.zip` для EXE или `FiercyLauncher-source.zip` для запуска из Python.
4. Проверяет SHA-256 по `SHA256SUMS.txt` (или GitHub asset digest).
5. Передаёт архив отдельному helper-процессу. Текущий EXE не пытается перезаписать сам себя: helper дожидается закрытия лаунчера, создаёт резервные копии заменяемых файлов и запускает новую версию.
6. Проверенный архив хранится в `%USERPROFILE%\.fiercylauncher\updates`. Если файл уже есть и SHA-256 совпадает, повторная загрузка не нужна.

Отдельный `FiercySetup.exe` работает как первичный установщик: он загружает последний Windows ZIP из GitHub Releases, проверяет SHA-256, хранит до трёх последних архивов в `%LOCALAPPDATA%\FiercyLauncher\cache` и копирует файлы в выбранную папку `FiercyLauncher`.

## GitHub JSON и вкладка FiercyCity

- `content/launcher.json` — минимальная версия клиента, режим обслуживания, объявление и рекомендуемый Minecraft.
- `content/news.json` — новости.
- `content/versions.json` — рекомендуемая версия и список поддерживаемых загрузчиков/версий.

GitHub Pages/Raw публичны. Они подходят для новостей, публичных настроек и списка сборок, но не для секретов, закрытого whitelist или защищённой статистики. Для будущего FiercyCity каталога потребуется API (например, Cloudflare Workers + D1/KV или Supabase); это можно сделать позднее, не меняя локальную модель профилей.

## Слабые ПК и ресурсы

Рекомендуемые настройки уже выставлены по умолчанию: режим слабого ПК включён, тени отключены, переходы страниц не анимируются, логи перечитываются раз в 7 секунд только когда открыта вкладка логов. Скачивание, установка, поиск модов, импорт сборок и перенос каталога с мирами/библиотеками выполняются в QThread. Лаунчер не опрашивает Minecraft в постоянном цикле и не сканирует все игровые файлы каждую секунду. Перенос данных показывает статус и не блокирует окно. Во время игры сам Minecraft будет потреблять ресурсы в соответствии с выбранными RAM, модами, шейдерами и настройками графики; лаунчер не может уменьшить нагрузку самой игры.

## Файлы и диагностика

- `main.py` — splash и запуск приложения.
- `launcher_window.py` — окно и страницы.
- `minecraft_service.py` — установка/запуск и подбор Java.
- `profile_manager.py` — реестр профилей.
- `mod_service.py` — операции с модами/каталогами.
- `modpack_service.py` — импорт модпаков.
- `instance_import.py` — импорт локальных версий.
- `github_service.py`, `update_helper.py`, `fiercy_setup.py` — обновления.
- `appearance_manager.py`, `ui_controls.py`, `toast_notifications.py` — оформление и UI.
- `tests/` — проверки путей и реестра профилей.
- `requirements.txt` — зависимости.

Лог лаунчера: `%USERPROFILE%\.fiercylauncher\logs\launcher.log`.

## Проверки в этой среде

Исходники проверяются командой `python -m compileall -q .`, а чистые unit-тесты — `python -m unittest discover -s tests -v`. Для реального Qt-запуска, Microsoft OAuth, установки Minecraft/Java и сборки EXE нужен Windows-компьютер с установленными зависимостями; статическая проверка не заменяет такой тест.


### NeoForge

Установка NeoForge для Minecraft 1.20.2+ использует штатный адаптер `minecraft-launcher-lib 8.x`. Перед запуском официального Installer в общей папке Minecraft создаётся совместимый `launcher_profiles.json`, затем библиотека устанавливает NeoForge и дочерние зависимости. Для Minecraft 1.20.1 и современных версий вида 26.3 используется резервный установщик с координатами Maven, поскольку текущий адаптер библиотеки рассчитан на классический формат Minecraft 1.x. Перед запуском версия проверяется по локальному JSON.


## Пользовательские и системные заметки бета-тестирования

- **FiercyCity:** содержимое страницы намеренно оставлено пустым. Добавляй собственные блоки в методе `_build_fiercycity_page()` файла `launcher_window.py`.
- **Discord:** без Discord Application ID нельзя программно отправлять кастомный Rich Presence. Чтобы Discord показывал базовое `Играет в FiercyLauncher` без собственного ID приложения, добавь `FiercyLauncher.exe` в Discord → Настройки пользователя → Зарегистрированные игры. После регистрации Discord определяет запущенный EXE сам.
- **Версии:** `version.py` — версия приложения; `content/launcher.json` — публичная минимальная версия. При публикации нового релиза обновляй оба значения согласованно. Версия `minimum_version` не должна быть выше реально опубликованного релиза.
- **Публичный бета-релиз:** для совместимости со старой версией `1.0.0.3`, использующей `/releases/latest`, релиз `1.0.0.4` должен быть опубликован как последний обычный релиз, а не как GitHub prerelease. В заголовке и описании можно явно указать, что это открытая бета.
- **Проверки:** тесты и компиляция Python не заменяют проверку на чистой Windows 10/11: установка Java/Minecraft/NeoForge, Microsoft OAuth, Discord Activity, DPI-масштабирование, обновление поверх `1.0.0.3` и создание ярлыка должны быть выполнены до публичного бета-анонса.
